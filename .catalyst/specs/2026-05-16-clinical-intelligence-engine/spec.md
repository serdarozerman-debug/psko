# Clinical Intelligence Engine

> Status: DRAFT

## Overview

Elevate PSKO from a basic chat simulation to an academically grounded clinical training environment. Three interconnected upgrades:

1. **Clinical Framework Library** — Each therapeutic approach is backed by a structured case conceptualization template drawn from academic sources (Beck's CBT model, Luborsky's CCRT, ACT Matrix, DBT biosocial model). The AI's system prompt is enriched with approach-specific session phases, evidence-based intervention sequences, and example clinical anchors.

2. **Pre-Session Intake Questionnaire** — Before starting a session, the student fills in a short structured intake (PHQ-9, GAD-7, presenting problem description). Claude analyzes the answers, generates a case formulation summary, and recommends the most clinically appropriate therapeutic approach(es). The student confirms or overrides the recommendation.

3. **Dynamic Session Guidance Panel** — The right panel during a session shows real-time structured guidance: which protocol phase the session is currently in, what the recommended next clinical move is, and which specific technique is being suggested. Guidance updates as the session progresses (tracked by turn count and content cues).

## User Stories

- As a student, I want to fill in an intake questionnaire before choosing a persona so that the system recommends the most appropriate therapeutic approach for that case
- As a student, I want to see a brief case formulation summary before I start so that I know what I am walking into clinically
- As a student, I want the session guidance panel to show me which protocol phase I am in (e.g. "Phase 2: Assessment — Elicit automatic thoughts") so I can follow a clinically structured session
- As a student, I want the guidance panel to suggest my next move based on what has happened in the session so far, not just generic technique hints
- As a student, I want the persona's responses to reflect academically grounded clinical presentations, not just personality sketches

## Requirements

### Functional

- [ ] REQ-001: Pre-session intake questionnaire with 10-15 structured questions (PHQ-9 style items + 3 open-ended presenting problem questions)
- [ ] REQ-002: Claude analyzes intake responses and generates: (a) case formulation summary, (b) top 2-3 recommended approaches with rationale, (c) contraindicated approaches
- [ ] REQ-003: Student confirms or overrides the recommended approach before session starts
- [ ] REQ-004: Case formulation summary stored on session and injected into the AI patient system prompt as additional clinical context
- [ ] REQ-005: Each approach module defines 4-6 sequential protocol phases with: phase name, clinical objective, key techniques, watch-for signals, transition criteria to next phase
- [ ] REQ-006: Session guidance panel displays: current protocol phase, recommended next technique, clinical watchpoint for this phase
- [ ] REQ-007: Phase progression is triggered automatically (by turn count thresholds + key content signals detected by a lightweight Claude call mid-session)
- [ ] REQ-008: Persona system prompts are enriched with SCID-5-inspired clinical anchors: symptom onset timeline, functional impairment level, trauma/medical history flags

### Non-Functional

- [ ] PERF-001: Intake analysis (Claude call) completes in < 5s
- [ ] PERF-002: Mid-session phase detection adds < 1s latency (async, non-blocking)
- [ ] UX-001: Intake questionnaire is max 3 screens / < 3 minutes to complete
- [ ] EDU-001: All framework templates reference peer-reviewed sources (Beck 2020, Linehan 2014, Hayes 2012, Luborsky 1984, Rogers 1961)

## Acceptance Criteria

1. Student fills intake → sees case formulation + approach recommendation → confirms → session starts with enriched context
2. During session, the right panel shows the current protocol phase label and a clinically specific "next move" recommendation
3. The panel updates at least once during a typical 10-turn session (phase transition)
4. Persona opening message reflects the intake formulation (not just the static persona backstory)
5. Each approach module has at least 4 defined phases with techniques per phase

## Technical Approach

### Clinical Framework Library (`src/lib/clinical/`)

New module replacing the simple `ApproachConfig` structure:

```
src/lib/clinical/
├── frameworks/
│   ├── cbt.ts          # Beck's 5-phase CBT model
│   ├── psychodynamic.ts # CCRT + psychodynamic listening template
│   ├── act.ts           # ACT Matrix + 6 core processes
│   ├── dbt.ts           # DBT biosocial model + skills modules
│   └── humanistic.ts    # Rogers' 3 core conditions + empathy ladder
├── intake/
│   ├── questions.ts     # PHQ-9 + GAD-7 inspired question bank
│   └── formulation.ts   # buildCaseFormulation(responses) → Claude call
└── phase-engine/
    └── detect-phase.ts  # detectCurrentPhase(transcript, approach) → Claude call
```

### Schema Changes

```prisma
model IntakeResponse {
  id         String   @id @default(uuid())
  sessionId  String   @unique @map("session_id")
  responses  Json     // PHQ-9 items + open-ended answers
  formulation Json    // Claude-generated case formulation
  recommendedApproach String @map("recommended_approach")
  createdAt  DateTime @default(now()) @map("created_at")
  session    Session  @relation(fields: [sessionId], references: [id])
}

model Session {
  // ... existing fields ...
  currentPhase Int  @default(0) @map("current_phase")  // 0-5
  intakeResponse IntakeResponse?
}
```

### Phase Engine

Each approach defines phases as:
```typescript
interface ProtocolPhase {
  index: number
  name: string                    // e.g. "Engagement & Rapport"
  objective: string               // Clinical goal
  techniques: string[]            // Specific techniques to suggest
  watchFor: string[]              // Warning signs / diagnostic cues
  triggerTurnMin: number          // Earliest turn to transition
  transitionSignal?: string       // Content cue that triggers advance
}
```

Phase detection: a lightweight non-streaming Claude call every 5 turns reads the transcript summary and returns the recommended phase index.

### API Changes

- `POST /api/intake/analyze` — new: receives intake form, returns case formulation + approach recommendation
- `POST /api/session/start` — updated: accepts `intakeResponseId`; injects formulation into system prompt
- `GET /api/session/[id]/phase` — new: returns current phase + guidance for the right panel
- `POST /api/session/[id]/advance-phase` — new: called when phase transition signal detected

### UI Changes

- `IntakeFlow` — new multi-step form component before persona selection
- `SessionGuidancePanel` — replaces static hints with phase-aware dynamic guidance
- Dashboard: "Choose a Patient" shows intake questionnaire before approach selector

## Out of Scope

- Full SCID-5 diagnostic interview (this is a training tool, not a clinical assessment instrument)
- Storing or displaying PHQ-9 scores as clinical diagnoses
- Voice interface (separate spec)
- Avatar / video simulation (separate spec)

## Open Questions

- Should intake be optional or mandatory? (Recommended: optional but strongly encouraged)
- Should intake responses persist across sessions with the same persona?
- Should the mid-session phase detection be a separate serverless function or inline with the message route?
